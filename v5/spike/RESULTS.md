# Spike: can Render run in the browser? (2026-10-19)

**Question:** is the slowest part of a Render - the Minkowski draft sums -
fast enough in WebAssembly to make a no-install browser version usable?

**Method:** `export_minkowski_inputs.py` captured the exact operands v4 sums
for a real Selectric I/II element (88 characters, full Render quality,
flatness 0.005 mm) and timed them natively. `bench.html` replayed the same
88 sums through manifold's official WebAssembly build in Chrome 152 on the
same laptop (16 logical cores).

| | time | notes |
|---|---|---|
| native (manifold3d 3.5.2, Python) | **30.4 s** | multithreaded |
| browser, manifold-3d 3.5.4 WASM | **85.5 s** (x2.8) | one thread, page not cross-origin isolated |
| browser, manifold-3d 3.4.1 WASM | 101.9 s (x3.4) | one thread |

**Same geometry:** volumes match native to within 0.0001% on all 88 characters.
Triangle counts differ (different triangulation, same solid).

**Slowest character:** "@", 5.1 s in WASM vs 1.9 s native.

## Conclusion: feasible

- **Preview** has no Minkowski sums, so it should stay quick.
- **Render** on one thread spends ~85 s in Minkowski for a Selectric ball.
  Slow, but it works.
- **The big lever is per-character parallelism.** Each character's sum is
  independent, so a pool of Web Workers, each with its own WASM instance,
  can run them side by side. Workers don't need cross-origin isolation (no
  SharedArrayBuffer), so this works on plain GitHub Pages. With 8 workers
  the Minkowski stage should drop to roughly 10-20 s. That estimate is
  untested.
